Assignment Overview¶

In this assignment we build a 3-layer MLP autoencoder to perform dimensionality reduction (compression) on the MNIST handwritten digit dataset. The autoencoder learns to compress each 784-pixel image into a smaller latent representation and then reconstruct the original image from that compressed code.

Tasks¶

  1. Train autoencoders with varying bottleneck sizes (5, 10, 20, 30, 60, 120 hidden units). Evaluate reconstruction quality using Mean Squared Error (MSE). Plot learning curves (MSE vs. epoch) for training, validation, and test sets.
  2. Visualize encoder weights for 10 and 20 hidden units — reshape each neuron's incoming weight vector into a 28×28 image to see what visual pattern each neuron has learned.

2. Load MNIST Data¶

The MNIST dataset is stored in a custom IDX binary format. Each image file has a 16-byte header containing the magic number, number of images, number of rows (28), and number of columns (28), all as big-endian 32-bit unsigned integers. The pixel data follows as unsigned bytes.

We load the raw bytes, reshape to (N, 784) (flattening each 28×28 image), and normalize pixel values from [0, 255] to [0, 1] by dividing by 255. This normalization is important because:

  • It matches the Sigmoid output range of our decoder (which outputs values in (0, 1))
  • It helps the optimizer converge faster by keeping values in a well-scaled range
In [3]:
def load_mnist_images(filepath):
    """Read an MNIST IDX3-ubyte image file and return flattened, normalized images."""
    with open(filepath, 'rb') as f:
        magic, num_images, rows, cols = struct.unpack('>IIII', f.read(16))
        raw = np.frombuffer(f.read(), dtype=np.uint8)
    images = raw.reshape(num_images, rows * cols).astype(np.float32) / 255.0
    return images


def load_mnist_labels(filepath):
    """Read an MNIST IDX1-ubyte label file and return integer labels."""
    with open(filepath, 'rb') as f:
        magic, num_labels = struct.unpack('>II', f.read(8))
        raw = np.frombuffer(f.read(), dtype=np.uint8)
    return raw.astype(np.int64)

4. Create PyTorch DataLoaders¶

We wrap our numpy arrays in PyTorch TensorDataset and DataLoader objects for efficient mini-batch training.

Key detail: For an autoencoder, the target is the input itself — we want to reconstruct x from x. So each dataset yields (x, x) pairs. No separate labels are needed during training.

Batch size = 256 — this provides a good balance between:

  • Training speed (larger batches = fewer gradient updates per epoch)
  • Gradient quality (not too noisy, not too smooth)

5. Autoencoder Architecture¶

The autoencoder is a 3-layer MLP (multilayer perceptron) with the following architecture:

Input Layer (L1):  784 units  ← flattened 28×28 image
Hidden Layer (L2): N units    ← bottleneck / latent representation  
Output Layer (L3): 784 units  → reconstructed image

Encoder: Linear(784 → N) + Sigmoid¶

  • The linear layer computes y = W₁·x + b₁ where W₁ has shape (N, 784)
  • Sigmoid activation squashes each value to (0, 1), creating a compact nonlinear representation
  • Row i of W₁ contains the 784 weights converging to hidden neuron i — reshaping this row to 28×28 reveals what visual pattern neuron i has learned to detect

Decoder: Linear(N → 784) + Sigmoid¶

  • The linear layer computes ŷ = W₂·a + b₂ where W₂ has shape (784, N)
  • Sigmoid output activation ensures reconstructed pixel values are in (0, 1), matching our normalized input range

Why Sigmoid?¶

  • Hidden layer: Forces the latent code into a bounded range, enforcing compression
  • Output layer: Natural choice since pixel values are in [0, 1] — prevents predictions outside valid range
In [6]:
class Autoencoder(nn.Module):
    def __init__(self, hidden_units: int):
        super(Autoencoder, self).__init__()
        
        # Encoder: 784 -> hidden_units with Sigmoid activation
        self.encoder = nn.Sequential(
            nn.Linear(784, hidden_units),
            nn.Sigmoid()
        )
        
        # Decoder: hidden_units -> 784 with Sigmoid activation
        self.decoder = nn.Sequential(
            nn.Linear(hidden_units, 784),
            nn.Sigmoid()
        )

    def forward(self, x):
        """Full autoencoder pass: x -> encode -> decode -> x_hat"""
        latent = self.encoder(x)
        recon  = self.decoder(latent)
        return recon

    def get_encoder_weights(self):
        """Return encoder weight matrix (hidden_units x 784) as numpy array."""
        return self.encoder[0].weight.data.cpu().numpy()

6. Training & Evaluation Functions¶

Training Loop¶

For each epoch:

  1. Forward pass: Feed a batch of images through the autoencoder to get reconstructions
  2. Compute loss: Calculate MSE between original and reconstructed images
  3. Backward pass: Compute gradients via backpropagation (loss.backward())
  4. Update weights: Adam optimizer adjusts weights in the direction that reduces loss (optimizer.step())
  5. Evaluate: Compute MSE on validation and test sets (without gradient computation for efficiency)

Loss Function: Mean Squared Error (MSE)¶

$$\text{MSE} = \frac{1}{n} \sum_{i=1}^{n} (x_i - \hat{x}_i)^2$$

This measures the average squared difference between each input pixel $x_i$ and its reconstruction $\hat{x}_i$. Lower MSE = better reconstruction.

Optimizer: Adam¶

Adam (Adaptive Moment Estimation) from torch.optim.Adam maintains per-parameter adaptive learning rates using first and second moment estimates of the gradients. This generally converges faster and more reliably than vanilla SGD for this type of problem, without requiring manual learning rate scheduling. We use the default learning rate of 0.001.

def compute_mse_on_loader(model, criterion, loader):
    """Compute average MSE over all batches in a DataLoader (no gradient computation)."""
    total_loss  = 0.0
    total_count = 0
    model.eval()
    with torch.no_grad():
        for x_batch, _ in loader:
            x_batch = x_batch.to(device)
            recon   = model(x_batch)
            loss    = criterion(recon, x_batch)
            total_loss  += loss.item() * x_batch.size(0)
            total_count += x_batch.size(0)
    return total_loss / total_count


def compute_mse_for_digit(model, criterion, images, labels, digit=3):
    """Compute MSE only for samples of a specific digit class."""
    mask       = (labels == digit)
    digit_imgs = torch.from_numpy(images[mask]).to(device)
    model.eval()
    with torch.no_grad():
        recon = model(digit_imgs)
        loss  = criterion(recon, digit_imgs)
    return loss.item()


def train_autoencoder(hidden_units, num_epochs=50, lr=1e-3):
    """
    Train an autoencoder and return the model + per-epoch loss histories.
    
    Uses:
      - Loss: MSELoss (mean squared error)
      - Optimizer: Adam with learning rate = lr
    """
    model     = Autoencoder(hidden_units).to(device)
    optimizer = optim.Adam(model.parameters(), lr=lr)
    criterion = nn.MSELoss()

    train_losses, val_losses, test_losses = [], [], []

    print(f"\n{'='*60}")
    print(f"Training autoencoder with {hidden_units} hidden units")
    print(f"Optimizer: Adam | LR: {lr} | Epochs: {num_epochs} | Batch size: {BATCH_SIZE}")
    print(f"{'='*60}")

    for epoch in range(1, num_epochs + 1):
        # --- Training phase ---
        model.train()
        running_loss = 0.0
        for x_batch, _ in train_loader:
            x_batch = x_batch.to(device)
            optimizer.zero_grad()
            recon = model(x_batch)
            loss  = criterion(recon, x_batch)
            loss.backward()
            optimizer.step()
            running_loss += loss.item() * x_batch.size(0)

        train_loss = running_loss / len(train_loader.dataset)

        # --- Evaluation phase ---
        val_loss  = compute_mse_on_loader(model, criterion, val_loader)
        test_loss = compute_mse_on_loader(model, criterion, test_loader)

        train_losses.append(train_loss)
        val_losses.append(val_loss)
        test_losses.append(test_loss)

        if epoch % 10 == 0 or epoch == 1:
            print(f"  Epoch {epoch:3d}/{num_epochs} | "
                  f"Train MSE: {train_loss:.5f} | "
                  f"Val MSE: {val_loss:.5f} | "
                  f"Test MSE: {test_loss:.5f}")

    return model, train_losses, val_losses, test_losses

8. Learning Curves — MSE vs. Epoch (Q1 — Part 1)¶

Below we plot the learning curves for each bottleneck size. Each subplot shows three curves:

  • Blue (solid): Training MSE
  • Orange (dashed): Validation MSE
  • Green (dotted): Test MSE (treated like a second validation set, as instructed)

What to look for:

  • All three curves should decrease together, indicating good generalization
  • If training MSE keeps dropping but val/test plateau or increase, the model is overfitting
  • Smaller bottlenecks (e.g., 5 units) converge to a higher MSE floor because they can't represent all image details
  • Larger bottlenecks (e.g., 120 units) achieve lower MSE because they have more capacity to preserve information

Observations — Learning Curves¶

  • All models converge smoothly — training, validation, and test MSE decrease together without significant divergence, indicating no overfitting. This is expected for a simple autoencoder on MNIST.
  • Smaller bottlenecks (5, 10 units) converge to higher MSE values because they are forced to compress 784 dimensions into very few features, losing fine details.
  • Larger bottlenecks (60, 120 units) achieve much lower MSE, as they retain more information from the input.
  • Validation and test curves closely track each other, confirming that the test set behaves similarly to the validation set (good data split).
  • Most learning happens in the first 10–20 epochs, with diminishing improvements afterward.

11. Encoder Weight Visualization (Q1 — Part 2)¶

The encoder's weight matrix W₁ has shape (N, 784), where N is the number of hidden units. Row i of this matrix contains the 784 weights that connect every input pixel to hidden neuron i.

By reshaping row i from a 784-dimensional vector to a 28×28 image, we can visualize what each hidden neuron has learned to detect:

  • Bright pixels indicate strong positive weights — the neuron responds when those pixels are active
  • Dark pixels indicate strong negative weights or near-zero weights

With 10 hidden units, the network must compress all of MNIST into just 10 features, so each weight image tends to look like a broad, prototypical digit shape. With 20 hidden units, the features become more fine-grained and capture more specific patterns.

This visualization corresponds to the course notes on autoencoders (pp. 78–79).

Observations — Encoder Weights¶

  • 10 hidden units: Each neuron's weight pattern resembles a broad, blurry digit or digit fragment. Since the network has only 10 features to represent all 10 digit classes, each neuron must capture general structural patterns shared across multiple digits (e.g., vertical strokes, loops, horizontal bars).

  • 20 hidden units: The weight patterns become more fine-grained and localized. With double the capacity, the network can dedicate neurons to more specific features — individual stroke orientations, specific curve patterns, or particular digit sub-regions. This additional specificity is what enables lower reconstruction error.

These visualizations confirm that the autoencoder is learning meaningful, interpretable features rather than random noise — exactly what we would expect from a well-trained dimensionality reduction model.

Summary¶

In this assignment, we built and trained 3-layer MLP autoencoders on the MNIST dataset to study dimensionality reduction. Key findings:

  1. Reconstruction quality scales with bottleneck size — increasing hidden units from 5 to 120 monotonically decreases MSE, with the most significant gains between 5 and 30 units.

  2. No overfitting observed — training, validation, and test learning curves track closely for all configurations, indicating good generalization. This is expected for a simple linear-nonlinear autoencoder on a relatively simple dataset.

  3. Encoder weights reveal learned features — with 10 units, the network learns broad digit-like templates; with 20 units, the features become more localized and specific, enabling finer reconstruction.

  4. Hyperparameters used: Adam optimizer (LR=0.001), MSE loss, Sigmoid activations, batch size 256, 50 training epochs, 80/20 train/validation split.
